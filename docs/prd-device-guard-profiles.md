- **C1（登录必须可指定端口）**：F3 说「出口端口 = 选择门户接入端口」，但 B6 显示登录请求写死在 8603。**若不改，规则里的端口就是摆设**。这是本次最大的一处实现面扩张。

- **C3（老凭据不能丢）**：B2 是单份密文文件；F3 要多份，必须写**兼容迁移**（见 P0-3.8）。

## 1. 目标与非目标

### 1.1 目标

| # | 目标 | 对应功能 |
| --- | --- | --- |
| G1 | 在「账号下在线设备数异常偏多」时，能**自动确认本机是否真的能出网**，并在会话失效时自动换一条可用会话 | F1 |
| G2 | 让巡检节奏**不再受预设下拉限制**，用户可自由输入，同时保留常用值的快捷入口 | F2 |
| G3 | 让**不同接入方式（有线 / 无线 / 指定 SSID）使用各自的账号、密码与出口端口**，覆盖「宿舍 Wi-Fi 一个号、办公室网线另一个号」这类真实场景 | F3 |
| G4 | 以上三项**全部默认关闭或默认走全局账号**，老用户升级后行为与现在**完全一致**，不丢密码、不需重新配置 | 全部 |

### 1.2 非目标（明确划边界，本次不做）

| # | 不做什么 | 理由 |
| --- | --- | --- |
| N1 | 守卫**不自动踢掉其他设备** | 用户只要求「断开本机连接后重新登录」；自动踢人是破坏性更强的操作，不在本次范围 |
| N2 | 守卫**不判定「谁蹭了网」**，不做设备归属分析 | 只做「设备数超阈值 → 探测连通性」这一条因果链 |
| N3 | 不做**多账号并发登录** / 多条连接同时在线 | 每台机器同时只有一条本机会话 |
| N4 | 探测方式（ICMP ping / HTTP 请求）**不做成界面选项** | 属技术决策，界面只暴露「目标地址 + 超时」两个可配置项 |
| N5 | 探测频率、失败判定次数（连续失败几次才算数）**不做成界面选项** | 同上，属架构决策；界面只暴露设备数阈值 |
| N6 | 不做规则的**优先级自定义 / 拖拽排序** | 匹配语义由「匹配方式 + SSID 唯一性」天然确定，无需排序 |
| N7 | 不改门户协议本身（`PortalClient` 的表单字段、隐藏域、验证码解析） | 换学校时只需改这一层的既有约定保持不变 |
| N8 | 不做「按流量 / 带宽 / 时段」的守卫 | 与本次需求无关 |
| N9 | 不做非 Windows 平台 | 项目定位即 WinUI 3 桌面应用 |
| N10 | 不做规则的**导入 / 导出**与云同步 | 凭据在本机 DPAPI 加密，跨机不可移植 |

## 3. 需求池

> 优先级定义：**P0 = 必须有**（缺了功能不成立）／**P1 = 应该有**（首批可后置）／**P2 = 可以有**。
> 每条给出**验收标准**（可测）。所有条目共同遵守两条底线：
> **底线 A**：新增能力默认关闭，或默认走全局账号；**底线 B**：既有行为不回退（老用户升级后账号密码、开关、巡检节奏均保持原样）。

### 3.3 F3 按连接方式区分账号与出口

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| F3-01 | 规则实体包含五个业务字段：**匹配方式**、**SSID**、**账号**、**密码**、**出口端口** | P0 | 一条规则能完整表达「无线 + 指定 SSID『校园网』+ 账号 X + 密码 Y + 端口 8605」 |
| F3-02 | 匹配方式**三选一**：**有线** / **无线（任意 SSID）** / **无线（指定 SSID）** | P0 | 三种规则都能创建、保存、匹配 |
| F3-03 | 规则**增 / 改 / 删**可用；删除需二次确认，且连带删除其凭据 | P0 | 删除后该规则凭据不可再被取出；删除别的规则不受影响 |
| F3-04 | 唯一性约束：**有线最多 1 条**；**无线（任意 SSID）最多 1 条**；**指定 SSID 的 SSID 不重复**（忽略大小写） | P0 | 重复添加被拒绝并有明确提示；不出现「两条规则同时命中」的情况 |
| F3-05 | 匹配输入 = **当前接入方式** = 网卡类型（有线/无线）+ 无线时的 SSID；**按当前生效（默认路由所用）网卡判定** | P0 | 拔掉网线只剩 Wi-Fi 时，命中的是无线规则而不是有线规则 |
| F3-06 | 命中优先级（同一时刻只允许命中一条）：**无线指定 SSID > 无线任意 SSID > 有线** | P0 | 同时存在「无线任意」与「无线指定『校园网』」时，SSID 为「校园网」时命中指定那条 |
| F3-07 | **未命中任何规则时**，沿用**全局默认账号 + 全局默认密码 + 全局默认端口**，行为与现状一致 | P0 | 规则列表为空时，登录请求与升级前完全一致（账号、密码、端口） |
| F3-08 | 命中的规则，其**账号、密码、端口**必须真正被登录流程使用（登录请求打到规则指定的端口） | P0 | 规则端口 = 8605 时，登录请求与状态查询均发往 8605，而不是 8603 |

## 4. UI 设计稿说明

> 这是 **WinUI 3 桌面应用**，不是网页。以下用**文字线框 + 控件清单**描述，沿用现有卡片体系（`CardStyle` 卡片 + 行式设置项 + 1px `DividerStyle` 分隔线 + `RowTitleStyle`/`RowDescStyle`/`HintStyle` 文字层级）。

### 4.0 整体布局与卡片顺序

右栏 `SettingsScroll`（ScrollViewer）内的卡片顺序调整为：

```
1. 在线设备            （已有）
2. 设备数守卫          （新增）
3. 连接规则            （新增）
4. 默认账号与出口      （已有，标题与字段措辞调整）
5. 自动化              （已有，巡检时长控件改造）
6. 关于                （已有）
```

调整理由：守卫与设备数相关、规则与账号相关，都放在「在线设备」之后、「默认账号」之前，形成「设备 → 守卫 → 规则 → 默认值」的因果顺序；用户最常改的「自动化」保持在靠后但可见的位置。

#### 4.1.1 处置动作的呈现（P1）

探测失败后自动断开重连属于后台行为，界面不弹窗打断；但需要让用户能主动触发一次完整处置（「现在就用守卫处置一次」）。规格：

```
│  [ 立即检测一次 ]   [ 现在重新建立连接 ]                            │
│                                        ↑ P1：手动走一次「断开 → 重连」
```

- 「现在重新建立连接」= 复用与守卫相同的处置路径（断开本机 → 重新认证），带同样的冷却与上限保护。
- 默认**隐藏**（只读日志），避免误触。是否首版就放出，由架构与开发按期决定（列 P1）。

### 4.4 自动化卡片：巡检时长改为可输入（已有卡片，控件改造）

```

│ ◇  自动化                                                            │
│  …                                                                    │
│  ──────────────────────────────────────────────────────────────     │
│  巡检时长                        [ −  20  + ] 秒                     │  ← NumberBox
│  已连接时多久检查一次状态，可填 4–120 秒                              │
│  常用： [4] [8] [15] [30]                                            │  ← 快捷值按钮组
│  ──────────────────────────────────────────────────────────────     │
```

| 控件 | 类型 | 名称（建议） | 关键属性 | 说明 |
| --- | --- | --- | --- | --- |
| 输入框 | `NumberBox` | `IntervalBox`（**复用原名**，减少改动面） | `Minimum=4` `Maximum=120` `Value=8` `SmallChange=1` `SpinButtonPlacementMode=Compact` | 原 `ComboBox` 同名替换为 `NumberBox`，`x:Name` 保留可让 `--ui-test` 的引用改动最小 |
| 单位后缀 | `NumberBox` 的 `NumberBox` 不支持后缀 → 旁边跟一个 `TextBlock` | `IntervalUnitText` | `Text="秒"` | 与现有「秒」文案保持一致 |
| 快捷值 | `Button` ×4 | `IntervalQuick4/8/15/30` | `Style` 用 `ButtonStyle`（弱化），`FontSize=11.5`，`Padding="10,3"` | 点击直接写入输入框并触发保存 |
| 说明文字 | `TextBlock` | `IntervalHint` | `Style=RowDescStyle` | 「已连接时多久检查一次状态，可填 4–120 秒」 |

**保留预设快捷值的方式**（明确结论）：不再用「可编辑下拉框」，改为 **NumberBox + 4 个快捷值按钮**。
理由：WinUI 3 的 `ComboBox` 可编辑态拿不到稳定的双向绑定（`IsEditable` + `Text` 绑定在 1.8 上并不可靠），而 `NumberBox` 原生支持 `Minimum/Maximum` 钳制与 `SpinButton`，正好对上 4–120 的整数约束。

**输入合法性**：`NumberBox` 自带钳制；另在 `TextChanged` / `ValueChanged` 时做一次显式校验（空值 → 保持上次合法值并提示），保证「不写坏设置」。

| 断开连接按钮 | 断开的是 `DeviceManager.Port` 上的本机会话；守卫处置时若生效端口 ≠ `DeviceManager.Port`，需按 C2 处理 |
| 设备数 | 卡片摘要里的「共 N 台在线设备」即守卫判定所用设备数，口径一致（含本机，见 F1-04） |

## 5. 数据模型草案

> 只列**字段名 + 类型 + 默认值 + 校验规则**，不写实现细节。字段名沿用现有 `PascalCase` 风格。

### 5.1 `AppSettings`（`settings.json`，现有类上新增）

| 字段 | 类型 | 默认值 | 校验规则 | 说明 |
| --- | --- | --- | --- | --- |
| `Account` | `string` | `""` | 非空则 trim；长度 ≤ 64 | **不变**；语义改为「默认账号」 |
| `Operator` | `Operator` 枚举 | `Mobile` | 必须是合法枚举值 | **不变**；语义改为「默认网络出口」 |
| `AutoStart` | `bool` | `true` | — | 不变 |
| `AutoReconnect` | `bool` | `true` | — | 不变 |
| `MinimizeToTray` | `bool` | `true` | — | 不变 |
| `KeepAliveOnLock` | `bool` | `true` | — | 不变 |
| `CheckIntervalSeconds` | `int` | `8` | 有效范围 **4–120**；越界回落 `8` | 不变；F2 后由界面自由输入 |
| **`DeviceGuardEnabled`** | `bool` | `false` | — | 新增（F1） |
| **`DeviceGuardThreshold`** | `int` | `2` | 有效范围 **1–50**；越界回落 `2` | 新增（F1）；语义：`设备数 > 阈值` 才触发 |
| **`DeviceGuardProbeTarget`** | `string` | `"223.5.5.5"` | trim 后非空；长度 ≤ 255；为空/超长回落默认 | 新增（F1） |
| **`DeviceGuardProbeTimeoutSeconds`** | `int` | `3` | 有效范围 **1–30**；越界回落 `3` | 新增（F1） |
| **`DefaultPort`** | `int` | `8603` | 必须 ∈ `PortalClient.KnownPorts`；否则回落 `8603` | 新增（F3）；全局默认接入端口 |
| **`ConnectionRules`** | `List<ConnectionRule>` | `[]`（空列表） | 条数 ≤ 20；每条须通过 §5.3 校验；整体非法时回落为空列表 | 新增（F3） |

### 5.2 `ConnectionRule`（连接规则实体）

| 字段 | 类型 | 默认值 | 校验规则 | 说明 |
| --- | --- | --- | --- | --- |
| `Id` | `string` | 新建时自动生成 GUID | 非空；全局唯一 | 凭据索引键 |
| `MatchType` | `ConnectionMatchType` 枚举 | `Wired` | 必须是合法枚举值 | `Wired` / `WirelessAny` / `WirelessSsid` |
| `Ssid` | `string` | `""` | 仅 `WirelessSsid` 时必填（trim 后非空）；长度 ≤ 32；在同为 `WirelessSsid` 的规则中不重复（忽略大小写） | `WirelessAny` / `Wired` 时恒为空串 |
| `Account` | `string` | `""` | 必填（trim 后非空）；长度 ≤ 64 | 规则专属账号 |
| `Port` | `int` | `8603` | 必须 ∈ `PortalClient.KnownPorts` | 规则专属出口端口 |
| `Enabled` | `bool` | `true` | — | P1；`false` 时该规则不参与匹配 |
| `PasswordRef` | `string` | `""` | 保存时必须指向一条存在的凭据 | 凭据索引（**不存明文**） |

**枚举取值**

| 枚举 | 取值 | 含义 |
| --- | --- | --- |
| `ConnectionMatchType` | `Wired` | 有线 |
| | `WirelessAny` | 无线（任意 SSID） |
| | `WirelessSsid` | 无线（指定 SSID） |

### 5.3 规则集校验（整体规则）

| 规则 | 说明 |
| --- | --- |
| R1 | `MatchType = Wired` 的规则**最多 1 条** |
| R2 | `MatchType = WirelessAny` 的规则**最多 1 条** |
| R3 | `MatchType = WirelessSsid` 的规则，`Ssid` 在该类型内**互不重复**（忽略大小写） |
| R4 | 任一规则的 `Account` 不得为空白 |
| R5 | 任一规则的 `Port` 必须 ∈ `PortalClient.KnownPorts` |
| R6 | 规则总数 ≤ 20 |
| R7 | 任一条规则非法时，**只丢弃该条**并记录日志，其余规则继续生效（不整体清空） |

### 5.4 凭据存储（多份 DPAPI）

**新增文件** `secrets.json`（与 `settings.json` 同目录）：

| 字段 | 类型 | 默认值 | 校验规则 | 说明 |
| --- | --- | --- | --- | --- |
| `SchemaVersion` | `int` | `1` | ≥ 1；未知版本时**只读不改** | 版本标记，便于将来迁移 |
| `Global` | `string` | `""` | base64 的 DPAPI 密文；空串表示「未设置全局密码」 | 全局默认密码（由旧 `secret.bin` 迁移而来） |
| `Rules` | `Dictionary<string, string>` | `{}` | key 必须对应一条存在的规则；value 为 base64 的 DPAPI 密文 | 规则密码，key = 规则的 `Id` |

**既有文件** `secret.bin`：**保留，不删除**（F3-13），作为迁移来源与降级回退。

| 项 | 值 |
| --- | --- |
| 加密算法 | DPAPI（`ProtectedData.Protect`，`DataProtectionScope.CurrentUser`） |
| 熵 | 沿用现有 `"SNNU.AutoLogin.v1"`，**不变**（保证旧 `secret.bin` 可解） |
| 落盘形态 | base64 文本（JSON 内），无明文 |

**兼容迁移契约**（P0，架构必须实现）

| ID | 契约 |
| --- | --- |
| M1 | 读取凭据时，若 `secrets.json` **不存在**且 `secret.bin` 存在且能成功解密 → 该密码作为**全局默认密码**使用，并写入 `secrets.json` 的 `Global` |
| M2 | 迁移过程**失败**（解密异常 / 写盘失败）→ **不阻断启动**，回退读 `secret.bin`，全局默认密码仍可用，日志提示一次 |
| M3 | 迁移**幂等**：`secrets.json` 已存在时不再重复迁移、不覆盖既有条目 |
| M4 | 迁移**不删除** `secret.bin`；升级后再降级回旧版，旧版仍能用原密码登录 |
| M5 | 迁移**不修改** `settings.json` 的 `Account`（全局账号保持原值） |
| M6 | 单条规则密码的写入/删除只影响该规则对应的条目，不影响 `Global` 与其他规则 |
| M7 | 规则被删除时，其凭据条目一并清除；清除失败只记日志，不阻断删除 |

### 5.5 运行时派生数据（不入盘）

| 名称 | 来源 | 说明 |
| --- | --- | --- |
| 当前接入方式 | 网卡类型 + SSID | 由架构判定「当前生效网卡」（见 §7 Q1） |

## 7. 待确认问题

> 只列**真正需要再拍板**的点。每条都给出「推断结论」，架构师可先按推断实现，收到答复再微调，不必阻塞开工。

### Q1. 守卫统计的「设备数」是否含本机？

- **推断结论**：**含**。设备数 = 「在线设备」列表条数，列表本身包含本机（`IsCurrent` 那条）。
- **为什么要问**：阈值 2 在两种口径下含义完全不同 —— 含本机时「> 2」= 至少 2 台别的设备；不含本机时 = 至少 3 台别的设备。触发频次差别很大。
- **影响**：仅影响 F1-03 的比较与界面文案，不影响架构。

### Q2. 守卫统计设备数时用哪个端口？

- **推断结论**：用**当前生效出口端口** —— 命中规则时用规则的端口，未命中时用全局默认端口；守卫卡片上明确显示「统计端口：8605」。
- **备选**：沿用「在线设备」卡片里用户手动选的端口（与登录端口无关）。
- **为什么要问**：两者可能不同，会让用户困惑（「我明明登录的是 8605，怎么统计的是 8603」）。
- **影响**：影响守卫的取数路径与界面文案，不影响整体结构。

### Q3. 规则的「出口端口」是否意味着**登录请求也要打到该端口**？

- **推断结论**：**是**。规则端口必须同时作用于「登录」「状态查询」「验证码」「断开连接」四条路径，否则这个字段没有实际意义（对应基线约束 C1）。
- **备选**：端口只影响「设备列表查询」，登录仍固定 8603（实现面小很多，但功能基本等于没用）。
- **为什么要问**：这是本次**最大的一处实现面扩张**，会牵动 `PortalClient` 的根地址（基线 B6）。
- **影响**：决定 `PortalClient` 是否需要改成「按端口实例化 / 带端口参数」——属架构级决策，需要产品侧确认功能意图。

### Q4. 规则是否需要**单独设置运营商出口（`yys`）**？

- **推断结论**：**不需要**，沿用全局「默认网络出口」设置（对应 F3-18）。
- **为什么要问**：门户的 `yys`（`mobile`/`unicom`/`telecom`）与接入端口是**两个维度**；若用户期望「有线走电信、Wi-Fi 走移动」，光有端口不够。
- **备注**：账号本身带 `@mobile` / `@unicom` / `@telecom` 后缀时，现有代码会用后缀覆盖全局出口设置（`PortalClient.LoginInternalAsync`），这在多规则场景下依然成立，可作为部分补偿。

### Q5. 巡检时长的实际下限：4 秒还是 5 秒？

- **推断结论**：把**在线态下限对齐到 4 秒**（改 `LoginCoordinator.NextDelay` 的 `Math.Max(5, …)` → `Math.Max(4, …)`），使存储范围 4–120 与实际生效范围一致。
- **为什么要问**：现状存储允许 4，但在线态实际是 5（基线 B5），用户填 4 却会看到「每 5 秒巡检」，属于自相矛盾。
- **备选**：把输入框下限改成 5，范围变为 5–120（与「沿用现状上下限」的表述略有出入）。
- **影响**：一行常量 + 一处文案；不影响架构。

### Q6. 守卫处置的冷却与连续失败上限取多少？

- **推断结论**：**最短冷却 10 分钟**；**连续处置失败 3 次后停止自动处置**，卡片上提示「已停止自动处置，请检查网络或手动重新连接」，用户可手动重置。
- **为什么要问**：网络本身不通时，守卫会反复「断开 → 重连」，把用户的网络越搞越糟（同时也是校园网异常流量的风险）。
- **影响**：两个常量 + 一处状态位；属产品策略值，需拍板。

### Q7. 规则密码是否允许留空（回落全局密码）？

- **推断结论**：**不允许**。用户已明确「每条规则独立存账号+密码」，保存时密码必填；编辑时留空表示「不修改」。
- **为什么要问**：允许留空可以少填一次，但会让「规则独立」这条前提变得含糊。
- **影响**：对话框的一条校验规则。
